# Summon 3.0.0 migration and rollback packet

This packet is the operator contract for moving a managed Summon installation
from the 2.2.x line to 3.0.0. It is deliberately separate from the release
manifest: the manifest proves the immutable release tree, while this document explains
how to move a host safely and how to return to the previous line.

## Supported upgrade shape

The installer owns the managed Summon payload under these host roots:

- Claude Code, Codex, Cursor, Gemini, Kimi Code, Copilot
- Antigravity CLI and Antigravity IDE

The project-local Cursor plugin and any `.agents` project-local copy are
reported as unmanaged drift. They are never silently overwritten by the
managed installer. Foreign files inside an owned tree are preserved according
to the ownership manifest; a changed owned file is reported as drift and must
be reviewed before replacement.

3.0.0 keeps the envelope/journal schema at version 1. Existing 2.2.x journals
remain readable by the replay and inspection paths. No envelope-v2 migration,
remote service, provider fallback, or automatic live-session continuation is
introduced by this upgrade.

## Preflight

Run from a clean checkout of the immutable release commit:

```text
python summon.py --doctor --json
python install.py --no-agents --dry-run
python -m unittest tests.test_migration_gate tests.test_install -q
```

The preflight must report the supported host matrix, the source version
`3.0.0`, and any unmanaged copies separately. Do not treat an unmanaged Cursor
plugin as converged managed state.

Telemetry remains explicit opt-in. A clean home has telemetry disabled. An
existing opt-in is preserved across upgrade; the installer does not enable it,
clear it, or transmit its local JSONL spool. Verify with:

```text
python skills/summon/scripts/run_subagent.py --telemetry-status --json
```

## Upgrade and interruption recovery

The installer writes a temporary payload, fsyncs it, atomically swaps the
owned directory, and records the previous payload for the duration of the
transaction. If the process is interrupted before the swap is committed, the
old tree remains usable. If an interrupted swap leaves a recoverable previous
tree, rerun the same installer command; it repairs the transaction before
reporting drift.

Never delete `.previous` or a foreign file by hand while an install is in
progress. The migration gate covers an interrupted swap and verifies that a
foreign file survives an upgrade.

## Rollback

Rollback is an explicit operator action:

1. Stop new Summon dispatches and close any local observation surface.
2. Record `summon.py --doctor --json` and the release evidence packet.
3. Restore the previously reviewed 2.2.x managed payload using the installer
   for that exact version, or restore the signed/archived managed-tree bundle.
4. Rerun `summon.py --doctor --json` and the 2.2.x compatibility suite.
5. Confirm that foreign files, project files, journals, telemetry preference,
   and unmanaged plugin drift are unchanged.

Rollback does not rewrite durable deliberation journals. A run created by
3.0.0 is either read by the 2.2.x compatibility reader or is surfaced as an
unsupported schema/feature; it is never guessed into a different decision.
Queued human commands remain queued, and a provider-in-flight or
uncertain-spend run remains blocked for explicit operator review.

## Evidence required for a release

The release packet must contain:

- `release-evidence.json` and its eight source-bound gate artifacts;
- this migration/rollback document and the passing migration gate;
- accessibility screenshots for desktop and mobile browser surfaces;
- the redacted live-provider receipt, when GA rather than provider-inert
  preview is claimed;
- the managed-install inventory and any explicitly reported unmanaged drift.

The final check is performed only after the source tree is committed and
immutable:

```text
python tools/release_manifest.py \
  --evidence-file release-evidence.json \
  --expected-version 3.0.0 --check
```

Any dirty/untracked source, missing gate artifact, mismatched source hash,
missing live receipt, or version mismatch is a release failure—not a warning.
