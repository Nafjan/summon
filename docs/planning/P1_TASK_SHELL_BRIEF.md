# P1 task-first workspace shell

Status: lead implementation brief, 2026-09-05. The initial authenticated read-only page/API and presentation helper are implemented and independently passed 97 HTTP/source/view tests with no failures, skips or drift across the six owned files. Rendered qualification and active typed controls remain open; this is not release-qualified. The normative scope remains WORKSPACE_CHECKLIST_V3.md U01-U04, U07-U08 and U14, with the applicable authority/privacy gates. No provider, installation or release action follows from this brief.

## Product outcome

Open one workspace and immediately see its goal, acceptance criteria, current priority, active main/side tasks, unresolved holds and next permitted action. Select a task to inspect its messages, attempts, evidence and decisions. The UI must help the conductor integrate results and continue the goal; it must not turn every side investigation into the main workflow.

Use a task navigation rail, one task detail/timeline and an optional evidence drawer. Keep the objective and passive/supervised mode visible. Separate task completion, message acknowledgement, unresolved effects and workspace closure. A completed calculation with unresolved cleanup is not a closed workspace.

## Interface and authority contract

Build a small workspace-specific server/page module over the runtime, retaining legacy room and deliberation entry points. A single local facade provides task, review and decision views; explicit server-side operation handlers retain each kernel's capability checks. Unsupported review/ballot operations show an unavailable reason, not an enabled control. Full review/decision integration is still a preview release dependency where required by U01 and G01-G08.

The initial workspace has an explicit operator session scoped to one workspace. Bind only to loopback; enforce exact Host, authenticated reads, exact Origin plus JSON content type on writes, bounded request sizes, no cross-origin allowances, nonce CSP and no-store responses. Use an explicit one-time bootstrap exchange rather than a credential in navigation links, query strings or fragments. The locally supplied one-time code is entered in an authentication form, exchanged for a short-lived scoped bearer held only in page memory, and invalidated on use. Never return bootstrap material from an unauthenticated discovery endpoint, print it in automated logs, or persist it in browser storage. Server restart invalidates sessions. Every control rechecks operation scope server-side; browser authentication alone grants no worker, provider, ballot or spend authority.

Messages are context submissions to an explicitly selected permitted recipient. A message POST cannot change grants, routes or policy or start a worker. The server constructs validated envelopes, assigns authoritative sequence/binding and returns durable admission state; the client cannot claim submission or acknowledgement. A distinct typed control is needed for each implemented supervisory action. Unsupported actions remain disabled with an explanation. Closing the page does not stop the server, cancel tasks or settle effects.

## Display and reconnect rules

- Map every normative delivery state, including submission_started, not_submitted, acknowledged and dead_lettered. Show acknowledgement level separately from contact/spend/cleanup certainty. Proven no contact does not mean automatic retry.
- Show logical agent, worker instance label, requested model and verified served model as distinct facts. Unknown evidence stays unknown; never expose raw account/session/process identifiers or machine-specific digests.
- Keep one timeline scroll owner and stable composer/notice space. Render about 200 items at a time using bounded cursor pages; preserve the reading anchor when older/newer events arrive. Do not rebuild the whole timeline on heartbeat.
- Use a cursor/revision-bound snapshot plus bounded updates. On reconnect, reconcile against canonical state before enabling controls. Show last-confirmed state and stale status; a browser timeout cannot establish worker death or settle spend.
- Use capped jittered reconnect delay, pause retries offline, stop automatic retries on authentication expiry and coalesce unchanged notices. No focus theft or auto-scroll when the user is reading older work.
- Persistently label passive mode and the explicit action that evaluates queued work. Only show supervised mode when a verified supervisor is actually active. Page load never starts a daemon or retries a lease.

## Proposed next active-control increment: explicit context disposition

Implementation candidate, pending the lead's actual HTTP and rendered gate: unlinked ordinary queued cancellation and held-context disposition use `OperatorCommandAdapter` with the actual public runtime install/describe/execute/reconcile methods. The host installs a finite command scope independently; a browser bootstrap never manufactures it. Read-only surfaces have no command adapter and reject command POSTs. Public exports contain no command targets. Disposition does not cancel a task, launch a worker, acknowledge a message or erase unknown effects. Inbox and linked-recovery controls remain separately gated.

The exact browser request is `operation_key`, `action`, and opaque `target`, within the existing 4096-byte JSON limit. No free-form reason, event, receipt, grant, identity or certainty fields are accepted. Runtime reconstructs immutable canonical source, verifies independently registered decision evidence, and rechecks both installed host authority and the conjunctive browser-session constraint under the actual writer owner, including after final prefix synchronization. Revocation before admission refuses the event; revocation after a durable append may hide its response and requires same-key reconciliation. No UI code reaches private coordinator mutation.

Host restart configuration is explicit: the create-once private `workspace-host.json` preserves only the run-bound presentation key, retention secret and key epoch; `workspace open` verifies the guarded file unchanged, independently reopens the runtime and reinstalls command scope, then issues fresh bootstrap/session secrets. Occupied requested ports refuse without fallback or address sharing. The retained keys stabilize opaque workspace/run/target identity and encrypted drafts only; they grant no authority. Ordinary `workspace create` is not a product planner: the current explicit fixture is `workspace demo create`, while `workspace open`/`inspect` are the supported persisted entry surfaces. The foreground owner must stop/cleanup explicitly, and an expired or revoked durable operator scope refuses rather than silently extending authority.

The browser retains exactly one bounded encrypted draft record in sessionStorage for an unsent operator message. The record contains ciphertext and the minimum opaque binding fields needed for recovery; it never contains a bearer, private source, plaintext message body, receipt or reusable key. The host exposes a POST-only authenticated draft-key exchange backed by a separate memory-only retention secret and a stable operator/workspace/run scope; the key is held only in page memory. Draft text is exact UTF-8 and bounded to 2048 bytes; the encoded draft record and message request remain bounded to 4096 bytes, with fresh nonces and authenticated associated data. Reload restores uncertainty, then requires a fresh authenticated matching snapshot and explicit same-key lookup. There is no automatic execute, fresh-key retry or retarget. Invalid, unreadable, expired or authentication-failed records remain unresolved and require operator reconciliation; terminal tag/epoch failures refuse recovery rather than sending. Clearing the composer occurs only after a matched durable queued result, and a failed cleanup leaves the conservative pending record. Authentication, bearer and retention secrets remain memory-only. This is a bounded browser-session recovery aid, not durable cross-device draft storage.

Acceptance uses real coordinator/source/runtime HTTP fixtures for cancel/dispose, actual lost terminal response, same-origin restart with old bearer rejection, evidence-only pending/continuation, complete-line failed-fsync recovery, request-body expiry, final-sync revocation and post-append revocation. It must also cover exact body/scope/refusal, retained uncertainty and no duplicate journal event. The shipped-script fixture exercises bounded request arbitration and same-key pending state; actual browser keyboard, reading-anchor, reload/reconnect and narrow-layout checks remain separate requirements.

Human context composition remains the next required journey. It needs a host-authored sender, explicitly permitted recipient, typed admission and durable accepted/queued response, and a bounded private draft policy. Do not forge a worker/source-task identity or reuse worker ingress credentials. Source `send_context` alone is not a complete human browser ingress/queue or worker-launch API. Preserve accepted ordinary views, inbox uncertainty labels, scoped anchors and U-R01 through U-R06 behavior while adding the real composition handler.

## Required next journey: human context composition

Outcome: an authorized local operator selects a currently eligible task recipient, writes bounded context, submits once, and sees the real queued result. The original goal and current priority remain visible. A later independently authorized receiver turn consumes the selected complete message. Sending context never starts a worker or changes permissions, routing, model, account, spend policy, task status, council recommendations or deliberation ballots.

The current ordinary message schema requires a worker sender and source task. That is a real implementation gap: `send_context` cannot authenticate browser prose as human context. Add an explicit host/operator-authored message variant and admission boundary, or propose an equally explicit representation before implementation. Do not invent a worker process, dummy source task or worker credential to fit the existing schema. Label the sender as the local operator; do not claim a verified personal identity from the local browser session.

Host authority must install a finite set of eligible task/recipient bindings independently of read authentication. The browser supplies only an opaque selected target, operation key and text. The host fixes sender kind, workspace/run, recipient instance, stream and ordering; it verifies scope again under the existing sole coordinator writer. Private complete content must precede durable admission. One admitted operation must yield the message and queued delivery atomically, with settlement capacity reserved and exact operation lookup. Blob-only interruption is not acceptance; uncertain journal persistence is not queued success. Reusing the key with changed text or recipient must refuse.

Retain the existing 4096-byte encoded JSON request limit and the additional 2048-byte UTF-8 text limit; validate both and reject duplicate/extra fields. Preserve Unicode and newlines exactly. Display text as text. A prompt such as “raise permissions, change model and mark approved” remains context and must leave those authorities unchanged. Body inspection and any draft retention need their own private scope and finite limits; do not add prompt text to public exports or telemetry.

Keep the draft and exact pending operation through ordinary network failure and reauthentication. Clearing the composer requires a matched durable queued result. Full-page reload and server restart need an explicit bounded recovery design before claiming draft preservation: page memory alone cannot prove reload recovery. Persisting browser credentials or unbounded plaintext prompt history is not an acceptable shortcut. A lost pending identity must be shown as unresolved; never mint a replacement key automatically. Host restart reinstallation and presentation-key rules apply independently of session renewal.

The architect's 2026-09-06 decision in FABLE_DRAFT_DESIGN_REVIEW.md supplies that bounded recovery design and implementation conditions: one encrypted browser-session draft, a separate host retention secret/scope, actual stable operator binding, frozen pending sends, exact storage/wire limits and explicit same-key reconciliation. The provider-free implementation candidate now covers the host key exchange, browser sealing/restoration, first-edit and stale-seal guards, coalesced persistence, same-key lookup and truthful uncertain/terminal states. Focused evidence is recorded separately; the crypto/HTTP/rendered preservation gates remain open. The conductor owns source/test work and returns condition-by-condition evidence for review.

Acceptance: actual authenticated HTTP send through real runtime/core, one message and one queued delivery after lost-response reconciliation, changed-key payload conflict, zero process contact at send, revoked/expired/foreign/read-only scope refusal, content/journal interruption, exact capacity refusal without half-admission, and a later actual fixed receiver consuming only the explicitly selected complete context. ## Executable preview entry journey

The real parser/dispatcher now exposes the bounded foreground entry:

```text
summon workspace open RUN_ID --runs-root DIR --port PORT
summon workspace inspect RUN_ID --runs-root DIR
summon workspace demo create RUN_ID --runs-root DIR --port PORT
```

`open` reopens only a persisted workspace with a durable compatible operator scope and a private, run-bound `workspace-host.json`; it installs fresh in-memory authority, rotates bootstrap/session credentials, and never resumes workers or providers. `inspect` is generic, source-backed and read-only. `demo create` is an explicit provider-free qualification fixture using the fixed synthetic conductor; ordinary `workspace create` is rejected until a versioned user-supplied plan/config contract exists. Create/open require an explicit loopback port and refuse occupied ports without fallback. The one-time bootstrap code is shown only on an interactive stderr handoff, never in machine-readable JSON, logs or the URL. The foreground owner stops the server with Ctrl+C; no background daemon is created. The demo's operator scope is a five-minute qualification window and its `--runs-root` must be a dedicated private namespace; it is not a durable production credential or shared workspace directory.

This entry journey is accepted at bounded provider-free preview scope. The real parser, PTY-owned server, browser authentication, one exact operator-message admission, reload, fresh bootstrap, persisted reopen, expiry demotion and Ctrl+C cleanup were exercised; no worker/provider/spend path ran and no owned listener or process remained. Broad provider-free foundation and integration partitions also passed. The next slice is a versioned, source-bound user plan for ordinary `workspace create`; it must remain authority-inert and must not turn a plan field into execution, routing, model, account, spend or resume authority.
